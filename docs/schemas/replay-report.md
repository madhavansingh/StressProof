# StressProof — Replay Report Schema

The Replay Report is generated by the Watcher Agent after fetching and validating a published claim.

If a discrepancy or violation is found, this report is canonically serialized, stored, and committed on-chain via `replayReportHash` and `replayReportURI` in `challenge()`.

---

## Canonical JSON Structure

```json
{
  "caseFileCopyURI": "http://127.0.0.1:8000/case-files/0x...",
  "chainId": 84532,
  "claimId": "1",
  "claimedInFileUsd8": "600000000000",
  "claimedOnChainUsd8": "600000000000",
  "evidenceHash": "0x...",
  "fetchedFrom": "http://127.0.0.1:8000/case-files/0x...",
  "hashMatches": true,
  "infoMismatches": [],
  "modelId": "static-liquidation-v1",
  "recomputed": {
    "debtAtRiskUsd8": "3374300000002",
    "liquidatableAccounts": 4,
    "liquidationVolumeUsd8": "3174300000001",
    "residualBadDebtUsd8": "200000000001"
  },
  "registry": "0x...",
  "replayerCommit": "9a3f2b1...",
  "schemaVersion": 1,
  "verdict": "WRONG_RESULT",
  "violations": [],
  "watcher": "0x..."
}
```

---

## Verdict Categories

* `MATCH`: The evidence is valid and the recomputed residual bad debt exactly matches the claim. No challenge is posted.
* `WRONG_RESULT`: The evidence is valid and canonical, but `recomputed.residualBadDebtUsd8` does not equal `claimedOnChainUsd8`. A challenge is posted with `counterResidualBadDebt = recomputed.residualBadDebtUsd8`.
* `EVIDENCE_INVALID`: The evidence could not be fetched, failed Keccak-256 hash verification, or failed any structural validation rule V-01..V-13. A challenge is posted with `counterResidualBadDebt = 0`.
